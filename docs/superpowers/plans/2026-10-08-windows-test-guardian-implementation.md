**Goal:** Add a test-only Windows guardian that contains one `NativeSession::prepare` attempt per invocation and independently confirms root exit after the launcher disappears.

**Architecture:** Preserve the normal `Instant` runtime clock and add one per-session, test-only shared-QPC mode. An ignored guardian test owns the sole `J_test` handle and creates an ignored case-host test inside that Job using `PROC_THREAD_ATTRIBUTE_JOB_LIST`; the host waits for membership authorization, then runs one preparation attempt. If a root is created, the guardian opens and retains its own root HANDLE before acknowledging the existing test observer. Checkpoint 2 keeps the root suspended and does not send worker input.

**Tech Stack:** Rust 2024, `windows-sys = 0.61.2`, Windows Job Objects, `PROC_THREAD_ATTRIBUTE_JOB_LIST`, QueryPerformanceCounter, serde/serde_json, Cargo integration tests.

**Spec:** `docs/superpowers/specs/2026-10-08-windows-test-guardian-design.md`

## Global Constraints

- “This is a trusted diagnostic-code harness, not an isolation boundary for plugins or hostile code.”
- “It must not receive plugin/WASM bytes, launch arbitrary commands, grant host capabilities, or be integrated into the production loader.”
- “For each `NativeSession::prepare` attempt, the ordinary test launches a fresh ignored guardian test, and that guardian launches one ignored case-host test.”
- “The guardian creates an unnamed, non-inheritable `J_test` with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Set no resource quotas, UI limits, or breakaway flags.”
- Require Windows 10+/Server 2016+, creation-time `PROC_THREAD_ATTRIBUTE_JOB_LIST`, and verified nested `J_test`/`J_prod` membership; fail closed with no uncontained fallback.
- Use one QPC origin/frequency captured before guardian launch. Preserve setup +3 s, handshake +13 s, work +10 s from the matched observation, cleanup ≤2 s from the scheduled stop, and overall +25 s. No process boundary resets or extends a cutoff.
- Checkpoint 2 keeps the diagnostic root suspended. Do not call `ResumeThread`, send worker input, add scenario IPC, or change the approved `child_process_tree` path.
- Root exit requires the guardian's retained root HANDLE to signal; `J_test` emptiness and termination-call success are separate evidence.
- Preserve the external-origin gate, strict RSS/handle requirements, A01–A04 open, macOS NO-GO, and Linux sequencing. No staging or commits.

## Interfaces

Task 2 defines the clock types consumed by later tasks:

```rust
#[cfg(test)]
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(super) struct QpcOrigin {
    pub counter: i64,
    pub frequency: i64,
}

#[cfg(test)]
pub(super) struct OsVersion {
    pub major: u32,
    pub minor: u32,
    pub build: u32,
    pub product_type: u8,
}

#[cfg(test)]
pub(super) trait QpcSource: Send + Sync {
    fn counter(&self) -> Result<i64, u32>;
    fn frequency(&self) -> Result<i64, u32>;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(super) enum CaseTimestamp {
    Local(std::time::Instant),
    #[cfg(test)]
    SharedQpc(i64),
}
```

`QpcOrigin::capture(source)` captures one counter/frequency pair. `QpcSchedule::new(origin) -> Result<QpcSchedule, ClockError>` derives checked absolute cutoffs. `CaseClock::from_shared_qpc(origin, Arc<dyn QpcSource>) -> Result<CaseClock, ClockError>` validates the process-local frequency. `CaseClock::now() -> Result<CaseTimestamp, ClockError>`, deadline construction, remaining-time conversion and cutoff comparison preserve the timestamp domain and fail closed on invalid frequency, mixed domains, overflow or ambiguous QPC ordering. The QPC source is a small private test seam; no global or thread-local clock is introduced.

Task 4 defines a fixed, test-only guardian protocol with `GUARDIAN_PROTOCOL_VERSION = 1`, `MAX_GUARDIAN_FRAME_BYTES = 4096` (total wire frame including its 4-byte prefix), and these typed operations: `START_CASE`, `READY`, `PREPARE_AUTHORIZED`, `ROOT_OFFER`, `ROOT_OWNED`, `NO_ROOT_CREATED`, `CASE_RESULT`, `REAP`, `ROOT_SIGNALED`, and the fixed negative-test barrier release. `GuardianCase` is a closed enum of atomic one-prepare recipes, optionally grouped by closed subordinate enums (for example, an enumerated setup-failure point or validation mismatch). A recipe selects exact compiled hooks, overrides, deadline intent, and post-prepare behavior; never serialize closures, raw override structs, arbitrary error codes/fault lists, scripts, or test-function names. Every invocation gets a checked, nonreused `AttemptId`; the complete `CaseIdentity { case, attempt }` is carried by every frame and evidence record and must match exactly. The attempt ID is correlation only, never a dispatch selector or deadline origin. Expected operation-deadline intent is derived from the recipe; if carried on the wire, reject disagreement. QPC metadata is the captured real-system origin/frequency and is validated as a checked schedule; synthetic/local test clocks never become guardian deadline evidence. No frame contains plugin bytes, arbitrary commands, or production scenario input.

Use one internal options-based preparation core before acquiring native resources. It receives the selected clock, hook, and root observer in all builds; its `ValidationOverrides` import, options field/parameter, initialization, and consumption are all `#[cfg(test)]`. The non-test core must not reference `ValidationOverrides`. Normal `prepare()` selects the existing local `Instant` clock, and every test wrapper (`prepare_with_hook`, `prepare_with_root_observer`, and `prepare_with_validation_overrides`) routes through the same core. The `#[cfg(test)]` guardian entrypoint supplies shared clock, hook, `ValidationOverrides`, and root observer together; it must not call a wrapper that constructs `CaseClock::new()` or omit override behavior. Preserve the current conditional-compilation pattern at `native.rs:938–948`. `NativeFailure` and `CleanupEvidence` retain existing local-`Instant` evidence for normal tests and add distinct QPC evidence for guardian validation; local timestamps are never presented as shared-origin proof.
